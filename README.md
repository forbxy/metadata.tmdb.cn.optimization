# TMDB CN Optimization (metadata.tmdb.cn.optimization)

Kodi 电影刮削器 (TMDB CN Optimization)，特别针对中文环境优化，包含多线程刮削与 DeepSeek 文件名解析功能。

## 功能特性

*   **多线程刮削**：显著提升大媒体库的扫描速度。
*   **DeepSeek 集成**：利用 AI 解析复杂文件名，提高识别准确率。
*   **中文优化**：针对中文命名习惯和 TMDB 数据进行优化。
*   **兼容性**：支持 Kodi 20、21 和 22，保留了原版单线程刮削的所有功能。
2.独立的多线程刮削器与明斯克CE固件自带的拼音索引服务器冲突，使用前请在插件-服务插件中禁用

## 独立多线程刮削器使用指南 (How to)

本插件内置了一个实验性的多线程刮削工具，适合需要快速建立新库或批量更新的用户。

### 1. 配置
进入 **设置 -> 插件 -> 我的插件 -> 信息提供者 -> 电影信息 -> TMDB CN Optimization**。
点击 **设置**，进入 **多线程刮削** 标签页：
*   **线程数**：使用默认即可，或根据机器性能调整（**注：此项仅支持插件全局设置，单个视频源内的线程数设置将被忽略**）。
*   **DeepSeek 设置**（支持视频源级别独立配置）：
    *   启用 DeepSeek 以获得更好的文件名解析能力。
    *   **DeepSeek API Key 文件**：创建一个纯文本文件（例如 `deepseek_key.txt`），只需将 API Key 粘贴在里面，然后在此处选择文件路径(目前仅支持deepseek官方平台的api)。

### 2. 设置视频源
1.  在 Kodi 文件管理中编辑源内容。
2.  选择 **TMDB CN Optimization** 作为刮削器。
3.  点击确定保存设置。
4.  **重要**：当弹出 "**是否刷新此目录内的所有项目？**" 询问时，请选择 **否 (No)**。
    *   *说明：如果选“是”，Kodi 将调用刮削器的单线程版本（不支持 DeepSeek）。*

### 3. 运行刮削
1.  再次进入该源的 **更改内容** -> **设置**。
2.  进入 **多线程刮削** 标签页。
3.  点击 **运行多线程刮削工具**。
4.  此时多线程刮削工具会扫描所有刮削器设置为 **TMDB CN Optimization** 的源。

## 图片缩放

在**图片缩放** 标签页中，开启 **启用 wsrv.nl 图片缩放**（默认关闭）。此功能仅在图片代理使用 `wsrv.nl` 时生效。

各类型的最大宽度可以分别设置：海报、无标题海报、演职员头像、光盘图默认 **480 像素**；背景图、横向艺术图、横幅默认 **720 像素**；透明艺术图和艺术标题默认留空，保持原尺寸。填写正整数，任意类型留空表示不缩放。

单线程与多线程刮削均支持，TMDB、Fanart.tv、电影集和预览图使用对应类型的设置。通过 wsrv.nl 的 `w` 和 `we` 参数保持比例、只缩小不放大，详见 [wsrv.nl 文档](https://wsrv.nl/docs/fit#without-enlargement-we)。设置作用于新刮削的图片地址，已有媒体库条目需重新刮削才能更新。

## 图片缓存

在 **多线程刮削** 标签页点击 **运行电影图片缓存工具**，会按配置的线程数，通过 Kodi 的 `image://` 原生入口缓存媒体库的海报、背景图及电影集对应图片。

图片解码、缩放、输出格式和缓存数据库登记均由 Kodi 完成，支持 Kodi 原生解码的 WebP，无需 Python 图片库。普通 JPEG、RGB PNG 和无透明通道的有损 WebP 可缓存为 JPEG；解码结果带透明通道的图片保存为 PNG。部分无损 WebP 即使所有像素都不透明，仍可能因为原生解码结果带 alpha 通道而保存为 PNG，工具沿用 Kodi 的格式判断。

已经存在且文件非空的缓存会跳过；数据库记录对应文件已删除或为空时，会通过 Kodi 清理该条记录并重新缓存。

原生缓存仍会按 Kodi 的 `imageres`、`fanartres` 设置缩放，即使 wsrv.nl 已经缩放过也可能再次缩小。例如当前测试机的 720×1080 海报会缓存为 480×720；16:9 图片按背景图规则处理。工具保留这一原生行为。

## 注意事项与提示

1.  **单线程模式**：插件保留原来的单线程版本，按 Kodi 常用用法使用即可。
2.  **媒体信息提取**：多线程模式目前**不支持**提取视频的媒体信息（StreamDetails 等）。
3.  **目录设置**：
    *   多线程模式仅支持 **包含子目录 (Recursive)** 和 **排除更新 (Exclude from scan)** 这两个目录属性。
    *   其他复杂的目录级设置可能在多线程模式下被忽略。
4.  **云盘/网盘警告 (尤其是 115)**：
    *   如果多线程扫描的是 115 网盘（通过 WebDAV/CD2 等挂载），且文件结构是“一个电影一个目录”，**极易触发风控**。
    *   建议：除非您已提前把目录结构缓存好，否则请谨慎操作。

## 失败列表
刮削结束后会展示失败的文件列表以及详细的搜索/解析记录（包括文件名 ID、NFO ID、常规搜索词、DeepSeek 搜索词），方便排查问题。

成功数以电影保存到媒体库为准；数据库写入失败会计入失败数并展示原因，失败的电影可在下次扫描时重试。

在 Kodi 22 上运行多线程刮削时，会自动恢复本插件此前刮削成功但未在媒体库显示的电影版本记录，无需清空媒体库。
